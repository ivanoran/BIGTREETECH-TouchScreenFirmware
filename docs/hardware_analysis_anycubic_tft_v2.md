# Анализ железа Anycubic TFT v0.0.2 (по дампу стоковой прошивки)

> Источник: реверс-инжиниринг дампа стоковой прошивки `dump_full.bin` (256 КБ, вся внутренняя
> флеш STM32F103VCT6) + трассировка платы. Все факты, отмеченные «дамп», извлечены из
> дизассемблированного кода стока (Thumb-2, дизассемблер: Capstone).

## 1. Состав железа

| Компонент | Модель / чип |
|---|---|
| MCU | STM32F103VCT6 (Cortex-M3, LQFP100, 256 КБ Flash, 48 КБ RAM) |
| LCD | ILI9488, 16-бит параллельный (8080) через FSMC Bank1 |
| NAND | Toshiba TC58BVG0S3HTA00 (1 Гбит = 128 МБ, страница 2 КБ) через FSMC Bank2 |
| Тач | XPT2046 (программный SPI, бит-банг) |
| SD | SPI2 + CD |
| UART | USART1 (связь с принтером, G-code) |
| Пищалка | PA2 через транзистор (TIM5_CH3 PWM) |
| Кварц | 1 шт. (HSE 8 МГц → PLL 72 МГц), LSE отсутствует |

## 2. Структура стоковой прошивки (дамп)

| Регион | Диапазон | Назначение |
|---|---|---|
| Bootloader | 0x08000000–0x08010000 | свой вектор на 0x08000000, код ~0x08000-0x0800E000; содержит свои копии драйверов LCD и NAND |
| Приложение | 0x08010000–0x08024000 | свой вектор на 0x08010000 (SP=0x20006C08, reset=0x0801CFB1) |
| Свободно | 0x08024000–0x08040000 | стёрто (0xFF) |

Тексты (строки интерфейса) и ресурсы в дампе почти отсутствуют → хранятся в NAND.

## 3. Подтверждённая распиновка

### LCD (ILI9488, FSMC Bank1 NE1, окно 0x60000000)

| Сигнал | Пин | Как подтверждено |
|---|---|---|
| CS | **PE3** (GPIO out 50 МГц, вручную) | дамп: `GPIO_Init(GPIOE, {0x28=PE3+PE5, out})`; `ResetBits(GPIOE,8)` перед init, `SetBits(GPIOE,8)` после |
| RS (D/C) | **PE4 = FSMC A20** | дамп: команды пишутся по `0x60000000`, данные по `0x60200000`. Для 16-бит шины FSMC_A20 = HADDR[21] → 0x00200000 ✓ |
| RESET | **PE5** (GPIO out, импульс LOW→пауза(0x190)→HIGH перед init) | дамп: функция 0x08015252: `ResetBits(GPIOE,0x20); delay(0x190); SetBits(GPIOE,0x20); delay(0x190)` |
| D0–D15 | PD14, PD15, PD0, PD1, PE7–PE12, PD8, PD9, PD10 (+ вероятно PE13–PE15 = D10–D12, не прозвонены) | стандартная раскладка FSMC D0–D15 на LQFP100; 16-бит режим требует все 16 линий |
| NOE | PD4 | дамп: PD4 в маске AF pins (0xD8B3) |
| NWE | PD5 | дамп: PD5 в маске AF pins (0xD8B3) |
| Подсветка | **PC9** (GPIO out 50 МГц; при init LOW, после DISPON HIGH) | дамп: `GPIO_Init(GPIOC, {0x200=PC9, out})`, `ResetBits(GPIOC,0x200)` в начале, `SetBits(GPIOC,0x200)` в конце init |

FSMC-конфиг (SPL `FSMC_NORSRAMInit`, Bank1): MWID=16 бит, WREN, без EXTMOD
(EXTMOD-поля пишутся сбросом 0x0FFFFFFF, но флаг 0x4000 не ставится);
тайминги: BTR1 = AddressSetup=0, DataSetup=**0x01**, остальное 0 → BTR1=0x100.
Отличается от наблюдения BCR1=0x1011 лишь битом MTYPE (декодировано 0x1010) —
уточнить при отладке, некритично.

### Init-последовательность ILI9488 (из дампа, полностью)

```
0xE0: 00 13 18 04 0F 06 3A 56 4D 03 0A 06 30 3E 0F   (Positive Gamma)
0xE1: 00 13 18 01 11 06 38 34 4D 06 0D 0B 31 37 0F   (Negative Gamma)
0xC0: 18 17          (Power Control 1: VRH, VC)
0xC1: 0B 02          (Power Control 2)
0xC5: ...            (VCOM)
0x36: ...            (MADCTL)
0x3A: 55             (Pixel Format: RGB565, 16 бит)
0xB0: 00             (Interface Mode)
0xB1: A0             (Frame Rate)
0xB4: 01             (Display Inversion)
0xB6: 02 22          (Display Function)
0xE9/F7: A9 51 2C 82 (регулировки)
0x11 (SLPOUT) → delay 0x78 (~120 мс) → 0x29 (DISPON)
→ PC9 HIGH (подсветка), заливка тестовым цветом, delay 0x1770 (~6 с)
```

### NAND (TC58BVG0S3HTA00, FSMC Bank2, окно 0x70000000)

| Сигнал | Пин / ресурс | Как подтверждено |
|---|---|---|
| CE | **PD7 = FSMC_NCE2** (shared pin: PD7 = NE1/NCE2) | дамп: PD7 в маске AF pins; Bank2 в конфиге SPL |
| CLE | **PD11 = FSMC_A16**, команды пишутся по `0x70010000` | дамп: литералы 0x70010000 (CMD), 0x70020000 (ADDR) |
| ALE | **PD12 = FSMC_A17**, адреса пишутся по `0x70020000` | дамп: `strb r1,[0x70010000]`=команда, `strb r1,[0x70020000]`=адрес |
| DATA | `0x70000000`, **8-бит шина** (D0–D7 = PD14, PD15, PD0, PD1, PE7–PE10) | дамп: `ldr r1,[0x70000000]` (ReadID); конфиг MemoryDataWidth=0 (8 бит); маски GPIO совпадают с D0–D7 |
| R/B (NWAIT) | **PD6** (FSMC_NWAIT, input pull-up) | дамп: `GPIO_Init(GPIOD, {0x40=PD6, mode=0x48 IPU})` |
| ECC | аппаратная FSMC ECC, страница 2048 байт | дамп: ECCPageSize = 2<<17 = 0x40000 (SPL: _2048Bytes) |
| Тайминги | Common/Attribute: Setup=1, Wait=3, Hold=2, HiZ=1; TCLR=0, TAR=0 | дамп: поля структуры FSMC_NANDInit |

Порядок работы с NAND (из дампа, ReadID): команда → `0x70010000`, адрес → `0x70020000`,
данные ↔ `0x70000000` (по 8 бит). Всё совпадает с RM0008 (CLE=A16, ALE=A17) и с
гипотезой «PD11/PD12», кроме CE: **не PG9 (его нет на LQFP100), а PD7 (NCE2)**.

Важно: линии D0–D7, NOE, NWE **физически общие** с LCD. При обращении к NAND CS дисплея
(PE3) обязан быть HIGH, иначе LCD «увидит» мусорные циклы на общих линиях. Сток именно
так и делает — CS LCD дёргается вручную вокруг транзакций.

### SD-карта (SPI2)

| Сигнал | Пин |
|---|---|
| CS | PB12 (в дампе маска 0x1000 на GPIOB в SD-драйвере) |
| SCK / MISO / MOSI | PB13 / PB14 / PB15 (SPI2, SPL SPI_Init в дампе) |
| CD | PB11 (input pull-up) |

### Тач (XPT2046, программный SPI)

| Сигнал | Пин | Как подтверждено |
|---|---|---|
| SCK | PA5 | дамп: бит-банг `SetBits(GPIOA,0x20)` после каждого бита |
| MOSI | PA7 | дамп: маска 0x80 на GPIOA |
| MISO | PA6 | дамп: чтение через GPIO_ReadInputDataBit |
| CS | PC4 | дамп: `ResetBits(GPIOC,0x10)` перед транзакцией, `SetBits` после |
| PENIRQ | PC5 | трассировка платы (в дампе EXTI-код присутствует) |

Чтение: команда → 0x00 → 0x00, сборка 12-бит значения из 2 байт (`(b0<<8|b1)>>4`) — классика XPT2046.

### Прочее

| Функция | Пин | Примечание |
|---|---|---|
| UART принтера | PA9 (TX) / PA10 (RX, pull-up) | USART1, подтверждён литералами в драйвере |
| Reset принтера | **PA8** | трассировка платы (подписан «reset» на разъёме). Это НЕ reset LCD |
| Пищалка | PA2 | TIM5_CH3 PWM (литералы TIM5 в дампе рядом с кодом пищалки) |
| SPI3 | PB3, PB5, PA15 (+PC7?) | сток конфигурирует SPI3, но на плате устройство не найдено — остаток универсального кода |
| PE0 | input pull-up | настраивается стоком, назначение неизвестно |
| HSE | 8 МГц кварц → PLL 72 МГц | стандартный путь SPL RCC |

## 4. Расхождения с исходными предположениями

| Было (гипотеза) | Стало (дамп) |
|---|---|
| LCD RESET = PA8 | PA8 — reset принтера. LCD RESET = **PE5** |
| RS = PE4 (A20) — «но данные идут по 0x60200000» | Оба верны: PE4 = FSMC_A20, а окно данных 0x60200000, потому что для 16-бит шины FSMC_A20 = HADDR[21] |
| NAND CE/ALE/CLE = PG9/PD11/PD12, «сток их не настраивает» | CE = **PD7** (NCE2), CLE = PD11, ALE = PD12 — сток настраивает их как AF (маска GPIOD 0xD8B3) |
| NAND неизвестно как подключён | FSMC Bank2, аппаратный режим, ECC 2 КБ, 8-бит, адресные окна 0x70000000/0x70010000/0x70020000 |

## 5. Что это значит для порта на BTT прошивку

Сравнение с эталоном `pin_TFT35_V1_x.h` (тоже STM32F103VC, тоже FSMC, тоже SPI2-SD, тоже
USART1): совпадает бо́льшая часть. Отличия Anycubic:

1. **LCD CS = PE3 вручную** (у BTT — PD7 = FSMC NE1 автоматически). PD7 у Anycubic занят NAND (NCE2).
2. **RS = A20/PE4** (у BTT — A23/PE2): меняется база окон (`LCD_BASE`).
3. **LCD RESET = PE5**, у BTT на TFT35 V1.x reset LCD не заведён явно.
4. **NAND вместо W25Qxx NOR**: шрифты/иконки/настройки BTT хранит в SPI NOR (SPI1+PA4).
   Решение — реализовать API `W25Qxx_*` (`w25qxx.h`: Read/Write/Erase/ReadID/ReadCapacity)
   поверх драйвера NAND. Интерфейс компактный и полностью эмулируем; ёмкость NAND
   (128 МБ) заведомо больше W25Q64 (8 МБ).
5. **Подсветка PC9**, у BTT — свой пин.
6. Тач: у BTT XPT2046 уже бит-банг, просто другие пины.
7. Пищалка PA2 (TIM5_CH3), reset принтера PA8 — донастроить в варианте платы.

Сборка: репозиторий уже на PlatformIO (GCC) — собрано в песочнице без изменений
(`BIGTREE_TFT35_V1_2`: RAM 32.8%, Flash 70.8% от 232 КБ; для сборки «без boot» доступно
все 256 КБ).
