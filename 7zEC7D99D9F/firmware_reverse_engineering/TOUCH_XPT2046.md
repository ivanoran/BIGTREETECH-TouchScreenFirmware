# TOUCH_XPT2046 — восстановлено из образа B

**Главное отличие от гипотезы из задания:** XPT2046 управляется **программным SPI на GPIO (bit-bang)**, аппаратный SPI1 (PA5/PA6/PA7) **не используется** (в B нет обращений к SPI1; регистры SPI1 не встречаются).

## Линии
| Сигнал | Вывод | Доказательство |
|---|---|---|
| SCK | PA5 (маска 0x20 GPIOA) | `SetBits/ResetBits(GPIOA,0x20)` 0x08016568 / 0x0801652A |
| MOSI | PA7 (0x80) | `SetBits/ResetBits(GPIOA,0x80)` 0x08016556 / 0x0801655C, значение — бит 7 передаваемого байта (`lsls r0,r6,#24; bpl`, 0x0801654C–0x08016554) |
| MISO | PA6 (0x40) | `GPIO_ReadInputDataBit(GPIOA,0x40)` 0x0801653C |
| CS | PC4 (0x10 GPIOC) | `ResetBits(GPIOC,0x10)` 0x08016582 (начало), `SetBits` 0x080165BE (конец) |
| PENIRQ | PC5 (0x20 GPIOC), **опрос, не EXTI** | `GPIO_ReadInputDataBit(GPIOC,0x20)` 0x08016BBC; `EXTI_Init` (0x0801069C) не имеет вызовов, обработчик 0x08016ABA (вектор EXTI4) проверяет линию 5 и в любом случае не включён |

⚠ `Touch_GPIO_Init` (0x08016A2C) сначала настраивает PC4 как OUT_PP (0x08016A50), а в конце **повторно как IPU** (0x08016AAA, `RCC_APB2PeriphClockCmd(0x10)` перед ним). Итог: CS «подтягивается» ODR (BSRR/BRR управляют подтяжкой вверх/вниз), а не активным выходом. Это либо ошибка оригинала, работающая «случайно», либо особенность платы. **Проверить осциллографом**; при переносе задать PC4 как OUT_PP.

## Протокол
* `XPT2046_SPI_Transfer` (0x08016510): 8 бит MSB→LSB; на каждый бит: SCK=1, `0x08016EE0(2)` (задержка ≈2×18 циклов), SCK=0, задержка, выборка MISO, выставление MOSI, SCK=1.
* `XPT2046_ReadADC(cmd)` (0x08016578): CS=0 → короткая пауза → передача `cmd` → два байта 0x00 → `result = ((b1<<8)|b2) >> 4` (12 бит, 0x080165A8–0x080165B8) → CS=1.
* Команды: **0xD0 → X**, **0x90 → Y** (`XPT2046_ReadXY_raw` 0x0801662A: 0x08016630/0x08016638). Z1/Z2 (0xB0/0xC0) и режим PD/ref **не используются** (в B нет таких констант в вызовах).
* Фильтр `XPT2046_Read_Filtered` (0x080165C6): **30 замеров** (0x080165DE `cmp r4,#0x1E`), обменная сортировка по возрастанию (0x080165EA–0x08016604), среднее по `sorted[4..25]` = **сумма 22 значений / 22** (0x0801660E–0x08016622; индексы 4…0x19, делитель 0x16).
* `ReadXY_raw` возвращает 1 только если X≥10 и Y≥10 (0x0801663E–0x08016644), сырые значения пишет по указателям.
* Опрос: `Touch_Poll` (0x08016BB0) читает PC5, ждёт через `0x08017300/0x08017306` (тики TIM2), читает XY и пересчитывает с плавающей точкой (в вызовах программной арифметики double — `0x0801D34A/0x0801D2B6/0x0801D3B2` — старшие слова констант 0x40733333 и 0x40B33333 дают **307.2** и **4915.2** (=4096×1.2); как они входят в формулу — **не разобрано**).

## Калибровка
* Строка «Touch Screen Adjust OK!» (B 0x08016DA7, A 0x080080FF) ⇒ в обоих образах есть мастер калибровки. Коэффициенты хранятся, вероятно, в блоке настроек Flash 0x0803E864 (100 байт, `Param_ReadFlash`); **таблицы калибровки/формулы пересчёта не восстановлены** (UNRESOLVED).
