# CLOCK_TREE — точная настройка RCC (образ B, `SystemInit` 0x0801D074 → `SetSysClock` 0x0801CFD4)

Все утверждения подтверждены инструкциями из `disassembly/full_disassembly.asm`.

## 1. Последовательность
| Шаг | Адреса | Действие | Следствие |
|---|---|---|---|
| Сброс RCC | 0x0801D07A–0x0801D0A4 (SPL `SystemInit`) | CR\|=1 (HSION) @0x0801D07A; CFGR&=mask(литерал) @0x0801D084; CR&=mask(литерал) @0x0801D08C; CR&=~0x40000 (HSEBYP) @0x0801D092; CFGR&=~0x7F0000 @0x0801D09A; CIR=0x009F0000 @0x0801D0A0; затем `bl SetSysClock` @0x0801D0A6 | RCC в состоянии reset, флаги прерываний RCC сброшены. Значения масок-литералов в таблице не перепроверены (стандартные для SPL) |
| HSE | 0x0801CFD4.. | CR\|=0x10000 (HSEON), ожидание HSERDY (0x20000) с таймаутом | внешний кварц (8 МГц по условию) |
| Flash | 0x0801CFE0.. | ACR: PRFTBE (0x10), LATENCY=2 | prefetch + 2 wait states |
| Делители | 0x0801D030 | CFGR\|=0x400 | **PPRE1=/2**; HPRE=/1 и PPRE2=/1 (не трогаются, 0 после сброса) |
| PLL | 0x0801D040 | CFGR&=~0x3F0000; CFGR\|=0x350000 | **PLLSRC=HSE**, **PLLXTPRE=/1**, **PLLMUL=0b1101 (×15)** |
| Запуск PLL | 0x0801D048.. | CR\|=PLLON, ожидание PLLRDY | |
| Переключение | 0x0801D05E.. | CFGR: SW=PLL, ожидание SWS=PLL | |
| VTOR | 0x0801D0B0 | `SCB->VTOR = 0x08000000` | затем `B_main` (0x08010148–0x08010150) вызывает `NVIC_SetVectorTable(0x08000000, 0x10000)` → VTOR=0x08010000 |

## 2. Вычисленные частоты (HSE = 8 МГц, предположение из задания)
| Шина | Формула | Значение |
|---|---|---|
| SYSCLK = PLLCLK | 8 МГц × 15 | **120 МГц** |
| HCLK | SYSCLK / 1 | 120 МГц |
| PCLK1 | HCLK / 2 | 60 МГц |
| PCLK2 | HCLK / 1 | 120 МГц |
| Таймеры APB1 (TIM2–7) | PCLK1×2 (т.к. PPRE1≠1) | 120 МГц |
| Таймеры APB2 (TIM1/8) | PCLK2 | 120 МГц |
| ADC | ADCPRE не задаётся (по умолчанию /2) | 60 МГц (ADC в образе B не используется) |
| SysTick | не включается в B (`SysTick_Config` 0x08017198 не имеет вызовов) | — |

## 3. Несоответствие спецификации STM32F103VCT6 и объяснение
* Штатные пределы STM32F103: SYSCLK ≤ 72 МГц, PCLK1 ≤ 36 МГц, PLLMUL ≤ ×16 при PLL ≤ 72 МГц. Код программирует 120 / 60 / 120 МГц.
* **Вывод (гипотеза, подтверждена косвенно):** прошивка собрана под STM32F10x-совместимый кристалл со 120 МГц (напр. GD32F303VCT6: те же 256 КБ Flash / 48 КБ RAM / FSMC / DAC, max SYSCLK 120 МГц, APB1 ≤ 60 МГц, APB2 ≤ 120 МГц — сочетание 120/120/60 как раз совпадает). Доказательств идентификатора кристалла в бинарнике нет (нет чтения DBGMCU_IDCODE 0xE0042000 и FLASH size register 0x1FFFF7E0) — **проверить маркировку чипа на плате**.
* **Практический риск для STM32F103 в 120 МГц:** разгон вне спецификации; на настоящем STM32F103 использовать PLL×9 (72 МГц), PPRE1=/2 (36 МГц) и пересчитать таймеры и FSMC-тайминги (см. §4 и PORTING_GUIDE).

## 4. Влияние на тайминги прошивки (вычислено)
* `TIM2_Tick_Init(PSC=0x47, ARR=0x3E7)` (вызов в `B_main`): при предположении «таймер = 72 МГц» период = 72·1000/72 МГц = **1 мс**; при реальных 120 МГц период = 72·1000/120 МГц = **0,6 мс**. Значит единица `delay_ms_tim2` (0x0801730E) и счётчик 0x20000070 ≈ 0,6 мс, а не 1 мс (если кристалл правда работает на 120 МГц). Это согласуется с «единицы времени ещё не установлены» из задания: **единица = 1 период TIM2**.
* Buzzer TIM5: PSC=0x28, ARR=0x31F ⇒ 120 МГц/(41·800) ≈ 3,66 кГц (72 МГц ⇒ ≈2,2 кГц).
* USART1: BRR вычисляется SPL по реальным регистрам RCC → 115200 бод корректен при любой настройке.
* SPI2 (SD): стартовый делитель 0x38 (/256) ⇒ 60 МГц/256 ≈ 234 кГц (ниже 400 кГц, как требует спецификация SD для инициализации).
* Программные задержки `delay_soft` (0x080164DC), задержка касания `0x08016EE0` — счётные циклы, **не калиброваны по времени**, зависят от SYSCLK.
